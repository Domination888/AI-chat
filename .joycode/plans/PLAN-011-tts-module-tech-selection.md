# TTS 模块技术选型文档

## 需求概要
- **硬件**: Mac M4 32GB 统一内存
- **核心需求**: ①音频克隆 ②流式返回 ③低TTFB（AI对话场景）
- **部署约束**: 必须跑在 Mac 端，需 MLX/Core ML/Metal 加速

---

## 方案详细分析

### 方案1: 继续优化 GPT-SoVITS（现状方案）

**优势**:
- 黍模型已训练完成，音质已验证
- 社区生态最成熟，LoRA训练方案完善
- 中文效果在微调后目前仍是最顶尖之一

**劣势**:
- **TTFB差**: 两阶段架构(GPT语义token → VITS声码器),首包延迟1-3秒
- **流式支持弱**: 本质是整句生成，需自行chunk拼接，衔接有瑕疵
- **无MLX优化**: PyTorch MPS 后端算子兼容性问题多，性能未充分释放
- **维护负担重**: GPT-SoVITS 项目本身架构老旧，v4版本混乱

**优化路径**:
- 尝试预生成语义token缓存减少TTFB
- 分段流式拼接优化
- 预期TTFB仍难低于500ms

**结论**: 作为过渡方案可保留，但架构天花板低，无法满足低延迟AI对话需求。

---

### 方案2: Qwen3-TTS-0.6B（推荐首选）

**优势**:
- **TTFB极低**: Dual-Track双轨架构，首包97ms，输入1个字即可出音频
- **3秒语音克隆**: 零样本克隆，无需微调，参考音频直接编码
- **10种语言+方言**: 中文、英文、日语等，克隆音色可跨语言迁移
- **0.6B轻量版**: Mac M4 32GB 跑0.6B版本内存~1.5GB，推理速度可控
- **指令控制**: 可通过自然语言调节语气/情感/语速
- **Apache 2.0**: 完全开源商用

**劣势**:
- **无MLX官方版**: 目前依赖PyTorch MPS后端，M4上性能待实测
- **0.6B音质略逊1.7B**: 0.6B为效率与质量平衡版，克隆相似度略低
- **项目较新**: 2026年1月开源，生态仍在建设中

**M4性能预估**:
- 0.6B模型：PyTorch MPS推理，预计生成速度 20-40 tok/s，TTFB ~200-400ms（含文本前端处理）
- 1.7B模型：内存~4GB可行，但推理速度可能降至 10-20 tok/s，TTFB ~500ms+
- **建议先用0.6B，音质不满足再升级1.7B**

**部署方案**:
```
Mac 本机 Python 服务 → HTTP API → 后端 Spring Boot 调用
流式: Qwen3-TTS 原生流式 → chunked PCM → SSE 推前端
```

---

### 方案3: Kokoro-82M（轻量备选）

**优势**:
- **极轻量**: 82M参数，量化后仅80MB，Mac M1即接近实时
- **ONNX Runtime**: CPU推理即快，无需GPU
- **Apache 2.0**: 商用友好
- **部署极简**: pip install kokoro-onnx 即可

**劣势**:
- **❌ 不支持语音克隆**: 仅预设音色包，无法克隆特定人物声音
- **中文质量偏弱**: 中文TTS效果明显不如GPT-SoVITS/Qwen3-TTS
- **流式需自实现**: 无原生流式，需分段拼接
- **对话场景弱**: 训练数据以朗读叙述为主，对话场景表现差

**结论**: **不推荐**。核心需求（语音克隆）直接不满足，中文质量也不达标。

---

### 方案4: F5-TTS-MLX / Spark-TTS（备选观察）

**F5-TTS-MLX**:
- 已有 MLX 适配版，Apple Silicon 原生加速
- 支持零样本语音克隆
- 参数量~0.5B，内存可控
- 但中文效果和流式支持均不如Qwen3-TTS

**Spark-TTS**:
- 0.6B参数，3秒克隆
- M4上可运行（有踩坑实录但最终可行）
- 无MLX适配，走PyTorch MPS
- 流式支持有限

**OmniVoice（小米，2026.5新发布）**:
- 覆盖600+语种，中英文顶尖
- PyTorch推理可达40倍实时
- 但刚发布，生态和Mac适配未知，需观察

**结论**: 作为备选观察，暂不首选。

---

## 推荐方案

### 主推: Qwen3-TTS-0.6B（Mac本地部署）

**理由**:
1. 唯一同时满足「语音克隆+流式+低TTFB」三要素的方案
2. 0.6B在M4 32GB上资源可控，不影响其他服务
3. 97ms首包延迟是AI对话场景的刚需
4. Apache 2.0 完全开源，可商用

### 降级兜底: GPT-SoVITS 保留

**理由**:
1. 黍模型已训练，音质有保证
2. Qwen3-TTS MPS 适配如遇问题，可快速回退
3. 后续可作为"高质量离线生成"的备选路径
