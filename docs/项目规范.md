# AI-Chat 项目规范

## 项目目标

将角色资料、剧情语料、语音输入输出、Live2D 表现和长期记忆整合成一个可长期陪伴式对话的桌面应用。项目优先服务本地开发和个人使用，打包版尽量减少用户手动部署的组件。

## 当前架构

```text
Electron Main
├─ BrowserWindow: Vue3 主界面
├─ 透明 Live2D 子窗口
└─ ServiceManager: 打包版启动内置服务

Vue3 Frontend
├─ 聊天、角色卡、设置、日志、MCP 管理
├─ SSE 消费: text / emotion / tts / done / error
└─ Live2D 控制与口型同步

Spring Boot Backend
├─ /api/chat 统一聊天 SSE
├─ RAG + Memos 长期记忆
├─ LangChain4j LLM / MCP tools
├─ SenseVoice ASR 编排
└─ Astra TTS 流式编排

Local/Bundled Services
├─ MySQL / Redis
├─ SenseVoice ASR
├─ MemOS
├─ SearXNG
└─ MCP JARs

External URL
├─ LLM
├─ Embedding
└─ Astra/Genie-TTS
```

## 后端规范

- 聊天入口统一使用 `POST /api/chat`，通过 `ChatRequest.inputMode` 区分文本与语音。
- RAG 和 tools 默认开启，联网搜索由前端开关决定。
- SSE 事件使用 `asr`、`emotion`、`text`、`tts`、`done`、`error`。
- 情绪标签在后端剥离，不让 `<开心>` 等标签直接出现在用户可见文本中。
- TTS 通过 `TtsStrategy` 扩展；当前默认和唯一活跃策略是 `astra`。
- Memos 写入只写用户消息，避免 assistant 内容污染用户记忆。
- 运行时配置通过 `/api/runtime-config` 合并保存，不要求重启。

## 前端规范

- 主界面在 `client/src/src/App.vue`。
- 设置页在 `SettingsModal.vue`，首次启动向导在 `SetupWizard.vue`。
- API 基址通过 `client/src/src/utils/api.js` 解析，打包版由 Electron 注入端口。
- Live2D 模型在透明子窗口 `Live2DOverlay.vue` 渲染，主窗口只做 IPC 桥接。
- TTS 音频播放要同时驱动 Live2D 口型同步，打断时清空播放队列。

## 配置规范

- 开发期服务连接以 `config/local-services.env` 为准。
- 用户可变配置以 `config/runtime-config.json` 为准。
- MCP 注册以 `config/mcp-servers.json` 为准，不再写死在 `application.yml`。
- 打包版的用户数据、日志、端口文件写入 Electron userData 目录。
