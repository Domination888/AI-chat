# 开发与文档规范

## 版本术语

项目只称商业版与离线版。商业版分用户端、管理端，二者共用商业后端；离线版作为整体。`cloud`、`offline`、`admin` 仅为对应构建标识。文档不再把“云版”“本地版”“开源版”列为额外版本。

## 代码边界

- 默认开发目标是 `apps/desktop`、`apps/server` 与 `packages/rp`。
- 旧库数据通过独立导出工具迁移。私人角色素材与个人配置的发行边界见打包说明。
- `external/` 是参考源码，不作为默认构建入口。生成文件、模型、用户数据与私钥不进入版本控制。
- npm 只在 `apps/desktop/` 安装依赖；Maven wrapper 在 `tools/maven/`。
- 世界状态与原始对话是权威数据；索引可重建，不代替原始记录。
- 账号归属从认证上下文取得，客户端的 userId 不决定权限；所有数据操作核对角色/篇章/世界归属。
- 修改世界前停止相关流并取得世界锁；分支生成独立世界，回退清理派生索引。
- 密钥不回显、不写日志、不进入导出。服务器变更不得静默复用另一地址的密钥。
- 离线运行默认回环，无遥测与自动联网更新。公网模型必须由用户明确开启。

## 数据操作

迁移采用源库只读导出、独立目标、完整备份、编号映射、逐条内容验证与原子切换。备份和报告保存在私人目录，权限仅允许本机用户读取。自动测试不得连接个人 MySQL/PostgreSQL 或应用数据目录；使用临时目录、专用 fixture 数据库。

## 文档职责

| 文件 | 内容 |
| --- | --- |
| README | 当前项目入口与运行命令 |
| architecture | 当前模块、部署边界与数据模型 |
| technology-stack | 面向 MySQL/Redis 使用者的组件概念、对照与源码阅读路线 |
| implementation | 当前技术机制与 API |
| packaging | 当前构建、部署、环境变量与许可 |
| migration | 数据迁移与恢复方法 |
| troubleshooting | 有复用价值的踩坑、症状、原因与处理方式 |
| scripts | 实际工具入口 |
| TODO | 未完成的开发、验收与待审阅功能 |

文档不保存版本演进叙述、过期设备分工或已完成计划。评测的原始证据保存在 artifacts；不能把小样本分数写成默认能力。历史只保留可复现的错误机制和解决办法。改路径时同步 wrapper、构建脚本、Docker、CI、源码导出与文档；同时检验导出的源码能独立构建。
