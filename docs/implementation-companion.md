## 陪伴、联网与主动能力

V2 保存环境、喜好和日报；V3 增量增加完整角色卡、消息来源、候选话题、技能、加密 MCP 配置和记忆反馈，保留既有迁移 checksum。

`CompanionService` 的明确喜好规则继续工作；`InterestInference` 在现实陪伴完成回合后通过当前用户的模型做语义提取，需逐字证据，跳过敏感与临时内容，尊重用户停用主题，每用户十分钟节流，也可手动刷新。推断计入当前模型额度，失败不丢失明确喜好。剧情模式不收集现实兴趣。

定位复用有截止时间和取消能力的设备请求。Electron 仅为自身 app 页面授权申请，并保留 macOS CoreLocation 和说明文案；拒绝、超时可手动城市降级。外部城市/天气查询单独开启后才访问固定 Nominatim/Open-Meteo 来源；离线版可使用 IP 粗定位，商业版不以服务端出口 IP 代替用户位置。聊天不重复发起设备定位。手动城市启用联网后经固定 Open-Meteo 地理编码查询天气，界面显示实际匹配地点、提供方和观测时间；可手动刷新，服务失败保留历史观测并明确说明。更换或清除地点时清除旧天气。现实陪伴中的当地时间/天气问答在 weather-lookup 技能启用时补入当前资料；天气观测超过十分钟才自动刷新，缺少天气时不替代成推测值。

询问共同往事时，持续的对话规则要求区分可核对事实与缺失资料；问题中的预设、当前节日和角色背景不能被补造成用户的共同记忆。停止召回不删除原始对话；原始对话、有效的更正和明确的新提议继续保留各自含义。上传图片后，`VisualTaskPrompt` 将当前图片与原问题作为任务，旧开场和角色背景仅作语气、指代参考；保留来源和用户约束，不能用角色剧情替代画面事实。

当前 macOS Electron 使用 Chromium 的 LocationProviderManager / PlatformOnly 系统定位模式；普通定位和近似定位权限仅限可信主框架，不以 Chromium 网络定位冒充系统设备位置。开发启动前幂等补齐用途说明并校验开发 app 签名，需要修复签名时先确认同路径客户端已退出，再进行开发 ad-hoc 签名。该准备不会修改系统定位开关或替用户授予系统权限；平台错误提示分别说明 macOS、Windows、Linux 或浏览器的处理方式。

天气同时提供来源的 UTC 观测时间与转换到用户所选时区的同一时刻，界面和问答上下文均可直接使用转换值，避免把 UTC 钟点说成当地钟点。没有有效来源时间的旧记录不补造观测时刻；清除地点同时移除该派生结果。

`AiDailyService` 读取 Juya RSS/Markdown，支持编辑技能中的来源、时区、日程和开场指令，限制下载大小、重定向和 XML 外部实体。缓存保留实际期刊日期和已读状态；当日未读日报入主动候选队列，通过角色开场 SSE、消息提交、来源关联、候选反馈和已读提交完成投递。问详情可结合近期日报上下文。应用/服务必须运行才能执行日程。

日报来源卡由实际注入模型的期刊条目生成并持久化，编号追问优先使用此前保存的期刊，避免刷新后指向另一条消息。普通新话题仅含“展开”“来源”不会自动继承日报。已核对日报资料的讨论保留角色和场景，使用当前问题与来源生成，隔离此前聊天回答及问答记忆，避免旧错误回答反复成为新闻依据。日报下载遇临时网络或 502/503/504 可重试一次，失败返回明确 503 并保留已有期刊；不会把旧缓存声称本次更新成功。

天气问答与来源卡使用同一份结构化观测：成功查询保存实际 Open-Meteo API URL，卡片附原观测时间及本轮缓存、刷新或失败说明，并随消息持久化后推送。网页搜索状态与天气 API 状态分别说明，不用普通搜索网页证明天气数值。旧缓存没有原始链接时提示刷新补齐，不猜测 URL；修改或清除地点同时清除旧观测来源。

`ProactiveService` 使用带 bearer 的 fetch SSE，跟踪用户活动、空闲和故事暂停；接入兴趣后台研究、候选去重/反馈、日报及自定义技能日程。用户输入会中断主动生成，避免同一世界并发。账号暂停/删除停止推送。较少推荐会停用对应研究主题。

标有 `scheduledSkill` 的旧通知保留可见历史，并以已投递通知引用供后续指代；不会作为本轮指令、场景经历或长期共同记忆。既有索引召回也按该元数据排除，新通知索引任务正常结束；定时输出中的场景 JSON 不推进共享状态。普通主动聊天仍保留正常语义。

`SearchRag` 将自然提问中的检索主题与答复格式要求分开，通过服务端 SearxNG 检索；中英混合技术主题首轮无可用来源，或明确要求官方文档但只有第三方候选时，最多再执行一条保留实体及其它中文限定词的聚焦查询，官方请求加入英文 `official documentation`。`plannedQueries` 只记录实际执行的查询。官方请求在满足主题锚点后优先使用主实体与 host 标签匹配、或真实标题的点分品牌拼接后匹配 host 的候选；这是通用排序信号，不由网页自称“官方”认证所有权，也不维护产品域名表。无法匹配时，来源说明与模型上下文明确当前仅有非官方或身份未确认的第三方资料。先判断来源元数据与主题的相关性，再校验公网 HTTPS；纯中文提问去掉通用问句及时间词后按主题双字片段检查独立命中和覆盖率，不让“今天”“请”等通用字相似度放行无关来源；点分品牌作为一个主题锚点，涉及多个技术词的比较不能只命中其中一个名称，无关网页也不能被误报成该问题的 DNS 故障。读取有界网页正文后结合词法与可用嵌入排序，注入来源并通过 SSE 返回引用；协议/端口不支持、内网或保留地址、Fake-IP、域名无法解析分别说明，不自动改写 HTTP 链接。搜索主题和日报指代在保留历史时解析，随后联网回答隔离旧助手回复及问答记忆；已知事实与来源缺失分别说明，不把未检索到当作不存在。日报和搜索的本轮任务约束统一预留提示预算，避免相互截断。无可验证来源时明确说明失败原因。商业任意公网抓取还要求配置出站 CONNECT 代理；本机搜索引擎地址是部署者配置的可信服务。

`McpRegistry` 按账号加密配置，提供增删改、连接、工具列表、手动调用和授权模型调用；离线支持本机 stdio、Streamable HTTP 和旧版 SSE，商业支持经受限出站代理的公网 HTTPS HTTP/SSE，不接受任意用户服务端 shell。新服务默认选 HTTP；http 与 streamable-http 配置标识等价，已有 sse 配置继续使用旧协议。编辑配置时留空仅保留同一远端地址的请求头；更换 URL 需重新填写凭据。本机 stdio 环境变量仅在命令数组完全相同时保留，不带入远端连接。HTTP 按 [MCP Streamable HTTP 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports) 支持 POST 的 JSON/SSE 响应、协商版本与会话头、初始化通知及 DELETE 结束会话；仅在带会话请求收到 404 时重建会话并重发一次，其它失败不重放工具调用。每次操作含响应体读取最多 20 秒，单条消息最多 1MiB，SSE 总量及帧数有界；可选 GET 常驻消息流与断线续传当前未启用。HTTP 会话固定到配置端点，SSE 的 POST 地址强制同源，两者均拒绝重定向并限制消息大小，避免远程服务把请求或凭据引向其他主机。旧 Prime 示例改为两版共有的 builtin 工具，精确验证正整数。模型工具规划有轮数/调用数/输出长度上限并计用量。`SkillRuntime` 提供技能正文、关键词、mcpTools 和日程的增删改。技能名称是创建后固定的唯一标识，编辑时只读并按原标识保存，避免改名意外创建重复定时任务。自建技能使用 triggerMode 明确区分每次聊天、关键词、仅定时、关键词和定时；旧配置含日程但无关键词时按仅定时解释，即使日程暂停也不会退回每轮触发。普通主动开场不把自动生成的请求当作用户关键词；定时投递仅使用目标技能，并保持 MCP 授权限制。界面提供每日时间、时区和投递开关；高级 JSON 折叠，保留 cron 和未知扩展字段，修改每日时间会移除优先级更高的 cron。定时来信显示对应技能名称。高级配置包含默认关闭的示例及执行条件说明。source.url 仅内置日报实际消费，不代表通用网页抓取。旧 SKILL.md/MCP/喜好迁移仅保留维护脚本，发行界面、桌面 IPC 和专用 HTTP 迁移接口均已移除。MCP 初始化失败区分端点停用、协议不符、鉴权、网络与超时；调用前按工具 schema 校验必填字段和基本类型，远端错误使用本地安全文案，不回显凭据或响应体。

黍优先载入旧角色卡、全部 lore 和开场语；`character://` 只提供固定资源根中的原模型/Core/动作/表情，拒绝目录穿越与符号链接越界。个人素材包显式构建，通用源码导出不含个人素材。PIXI 使用解释器适配 CSP，未放开 unsafe-eval；模型支持点击、动作、表情与音频口型。 发布界面动作列表合并与默认待机引用相同素材的 Tap#4/index4 别名，只保留一个待机入口；其余选项仍用共享动作列表原下标发送 group/index，内部情绪映射与素材文件保留。公开动作共 10 项；标签不承诺素材以外的独立动画。


### 日报与网页的本轮资料选择

日报优先明确请求的期次，不能默用current替代旧刊。已定位条目的问题先按原始中文/英文标点拆成子问，再逐问标准化，优先各选一条完整相关句；请求词处理不会破坏“申请”等事实词。预算装入按完整句执行，不能容纳的整句不截成半句。主要日报资料无论联网开关均使用 650 token 预算；显式额外网页仍限 500，日报来源组合整体限 1200，并保留本轮任务指令预算。具名标题优先匹配对应条目，按多子问题选择相关段落，并从原条目保留多样细节，不以整问总分截掉后一个子问题。日报任务优先用本期相关资料，不混入无关SERP；显式选刊和旧刊引用保留实际日期。刊期不等于新闻发生日，不能仅据刊期推断“昨天看到”或“今天发布”。主动消息持久化dailyIssueDate靠前显示；面板取得的日报快照同步侧栏，并以请求版本防旧轮询覆盖。相关资料缺失应明确未核实，不换成另一刊冒充完成。 含“日期+期+《完整标题》”但没有“日报”二字时，仅将其视为候选期刊意图；在已存当期/邻近日报或受限刊源读取中确认完整标题后才路由为日报，未知标题不凭供应商品牌泛匹配，也不把任意带日期的普通网页问题劫持成日报。

`WebFollowupContext`从此前实际来源与问题恢复“刚才两网页”等指代主题，继续检索和读取对应URL；旧助手答复不当新事实来源。来源指代只在最多三个邻近用户回合内寻找已保存的结构化网页来源；日报、主动和定时消息不参与，新增不同 URL 或明确换题停止继承。对不含固定指代词的短追问，在存在可信来源时才调用有界 semantic reference 分类；仅判定是否依赖原问题和实际来源，不让分类生成事实或选择任意新网页。无效/否定判断回普通检索，不凭关键词把新主题接到旧来源。 连续自然追问保留原始检索问题与真实来源，不把上一轮“本轮追问”反复拼成新主题；隐式日期追问只在有界邻近来源及日期话题内承接，换主题不继承。正文保留概览、标题及首标题附近少量日期/版本元数据与原事件标签；文章自身含主标题的 header 参与正文保留，站点 banner 仍剔除，区分公告日期和实际发布日期。检索、缓存与实时重读分开说明，天气分别标记当前设备时钟、观测 UTC 与同一观测的当地时间、查询行为及分钟 age；当前时钟不能称作缓存记录时间或观测时间，也不把数分钟前说成一小时前。上游无结果或CAPTCHA不单独证明应用故障。

### 当前场景与创作任务

普通对话将当前世界线已保存地点、故事时间及完整约定作为有界优先资料；单条约定不会截断成可能丢失否定或状态的半句，省略的条目不补造。用户说“这里”“刚才约好的事”时承接这些具体资料，优先于旧开场和旧助手叙述；用户本轮明确新设定或更正仍优先，待履行约定不当作已完成经历。未知共同往事仍需可靠记录；明确的故事、小说等创作任务允许合理设定虚构人物情节，不要求先存在真实旅行记录，也不据作品声称记起真实共同往事。创作成品任务单列要求直接输出作品；章节数、长作品收束与最终字数仍须按实际成品独立验证。

### 记录型问题与更正来源

`PastFactAnswer` 从当前世界线的有效用户陈述及个人资料提取有来源的记录，保留原始用户正文与 memory feedback 更正 provenance。明确陈述型更正可继承原陈述的资格，并标注为记忆更正；问题、假设、条件或创作请求不能因保存为更正就变成已发生事实，个人资料更正也不能扩散为共享经历。隐藏、定时技能、不可用等记录继续排除。

明确共同往事沿既有入口；简短指代问题只有存在可用同世界记录时才进入有界 `record_question` 分类，分类只能选记录编号，再由服务端引用原记录并附 historyIds/sourceTypes。普通照护建议、创作或其它新话题回普通任务路径，不用记忆缺失通知覆盖。可见记录和当前场景分别标注来源，不把角色即兴或助手旧答充当用户事实。

### 自定义技能的当前任务

普通消息命中启用的自建技能时，`SkillTaskPrompt` 将本轮要求作为独立任务，角色口吻和历史对话只作有界资料，保留用户事实、约定、保存的更正及最新明确纠正。旧开场不能作为本轮答案示例；需要引用上文的任务仍可读取有界历史资料。无匹配、定时、日报与搜索继续使用各自生成路径。

`SkillOutputContract` 只从明确、无歧义的输出指令提取 1–12 条要求；条数、问题和尾句分别合并当前用户指令。尾句区分无尾句、所需总结和精确 literal，支持中英单双引号及中文角引号中有界明确的“以…结尾/尾句为…”要求；引号里的数字不作正文数量。最新用户无需重复条数即可替换或取消尾句；“不要总结”只取消总结，不等于取消固定尾句。明确取消分条或技能格式时不强套旧约束。输入事实引用、不确定条件、多个尾句冲突及互斥的两个“最后内容”不被猜作严格格式，保留普通任务路径处理。

literal 同时写入严格 schema 的单值 enum 与本地校验，要求模型实际给出的原始值及清理后值均与字面完整相等，不能靠渲染器补造缺失尾句。literal 必须是最终可见内容；默认可选问题留空，明确要求一个问题时置于 literal 之前。普通总结后一个问题维持原顺序；禁止提问同时检查正文、尾句和问题字段，不允许把问题藏入别的字段。

明确条数的普通技能通过可选 `response_format` 请求结构化内容，完整接收后验证数量、非空与重复条目、问题和总结要求，再渲染为普通编号文本。模型生成的半截 JSON 不发送给界面，也不补造条目。服务明确拒绝严格格式时最多兼容一次 `json_object`，兼容请求同时在系统消息保留完整 schema、固定字面和条数要求，并执行同样本地验证，不重放 MCP 工具；HTTP 200 但结构不合格或生成截断时按失败保存，不自动反复生成。错误响应体同时受 16KiB、两秒截止和取消控制。结构化校验失败仍计入服务实际报告的生成用量，取消后不发布尚未确认的内容；MCP 的实际执行事实和原调用预算继续生效。

商业服务故障记录只保存固定分类代码；管理界面将认证、限流、上游异常、连接或超时、存储和已知输出问题转换为固定中文说明及处理提示。取消通过固定 `CancelCause` 记录第一个原因，区分用户停止、账号暂停/删除、客户端断连、超时、应用关闭及其它操作；管理端暂停不能显示为“用户主动停止”。正常完成不因关闭流而追加断连原因。用户中断与服务故障区分，旧 failed 记录明确未细分原因，不推测历史根因，不展示原始异常、URL 或凭据。

模型请求的安全 HTTP 异常同时用于聊天、工具规划和管理分类：401/403、429、5xx 与普通请求拒绝分别提示；只有结构化错误代码明确表示工具能力不支持时才使用该分类。工具错误正文读取受 16KiB、两秒上限约束，不把上游响应正文写入用户通知。

工具面板关闭、重新打开或更改服务后清除无效选择和执行结果，并以请求代次阻止旧异步响应恢复过时内容；删除服务或技能同时清除对应编辑表单。故事备份包含故事、照片、角色、技能和陪伴偏好，不包含模型连接、MCP 配置及其密钥。清空本地数据的确认明确列出删除范围；清空或导入后刷新模型与陪伴资料，清除旧对话、面板和播放状态，恢复时联网授权需重新确认。
